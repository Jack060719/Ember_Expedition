# 餘燼遠征 · Ember Expedition

直向單指操作的離線割草冒險。拖曳移動，一把主武器搭配多個自動技能；擊退怪潮、組合能力、進化武器，再用火種永久強化營地。

## 接手與協作

新加入的 agent 從 [AGENTS.md](AGENTS.md) 開始，依序閱讀 [專案目的與決策](PROJECT.md)、[目前狀態與交接](STATUS.md)、[下一版規劃](ROADMAP.md)。這些文件可隨專案移到 Orca 或其他環境，不依賴原有聊天紀錄；本 README 提供執行、安裝與現行數值說明。

## Android 安裝

Android 支援已於 2026-09-22 發布至[原手機網站](https://ember-expedition-nowifi.asterina-co.chatgpt.site)第 7 版，可用它執行下列安裝步驟。請以已獲授權的電子郵件所對應的 ChatGPT 帳號登入。[Android 私人測試站](https://ember-expedition-android-test.asterina-co.chatgpt.site)保留舊測試版本，存檔與正式站分開。

1. 用 Android 的 Chrome 一般分頁開啟上方原手機網站，依私人網站提示登入。若從通訊軟體開啟，先改用 Chrome。
2. 點右上角「⋮」→「加入主畫面」或「安裝應用程式」，依 Chrome 顯示的選項完成。
3. **從主畫面圖示再次開啟**，保持連網直到左上角顯示「已可離線遊玩」。
4. 開啟飛航模式並關閉 Wi-Fi，關閉遊戲後從原圖示重開，確認可進入營地與戰鬥。

這是共用原網站的主畫面 App，不需下載 APK。請固定使用同一個 Chrome 瀏覽環境與原網址；其他瀏覽器或裝置的進度需透過「設定與存檔」匯出／匯入 JSON。Android 分支的本機驗證、實機待辦與發布狀態見 [STATUS.md](STATUS.md)。

## iPhone 安裝

1. 用 Safari 開啟發布網址，依私人網站的提示登入。
2. 分享 → 加入主畫面。
3. **從主畫面圖示再次開啟**，保持連網，直到左上角顯示「已可離線遊玩」。
4. 開啟飛航模式並關閉 Wi-Fi，重新開啟遊戲確認。

Safari 分頁和主畫面 App 的儲存資料可能不同，請在主畫面版本開始正式遊玩。遊戲內「設定與存檔」可匯出／匯入 JSON 備份；清除網站資料會失去本機進度。

## 離線與日後更新（Android／iPhone 共用）

下載未完成時，點左上角離線狀態，查看原因並選「重新下載缺少的內容」。已安裝版本會補回缺檔；首次安裝失敗則重新下載，不影響遊戲存檔。離線狀態視窗會顯示目前離線版本，並提供「檢查更新」；返回遊戲時也會檢查新版。若顯示有新版本，完成或撤退結束目前遠征後，在同一視窗套用更新。「已可離線遊玩」只代表離線內容齊全，並不等於剛確認為最新版；檢查失敗會保留離線功能與錯誤提示。

網站保留登入限制。若提示「請重新登入以更新」，在離線狀態視窗選「重新登入以更新」；遊戲會先保存進度，存檔失敗就不跳轉。登入返回營地後會重試更新，已有遠征仍須結束後才可套用新版。一般斷網不會被判定為登入過期。

尚未取得此入口的舊版，可在一般 Safari 開啟[重新登入連結](https://ember-expedition-nowifi.asterina-co.chatgpt.site/signin-with-chatgpt?return_to=%2F)後回遊戲檢查更新，不必使用私密瀏覽或清除網站資料。這只恢復該瀏覽器環境；iPhone 主畫面 App 的登入跳轉是否維持同一儲存環境、已卡住的舊 App 能否恢復，仍須實機確認，不能視為已通過。

移動採用跟隨手指的浮動搖桿：輕推慢走、拉遠快走，鬆手或移出遊戲畫面會停止。長距離拖曳後不必拖回最初按下的位置才能轉向。

## 目前內容

以下為 TASK-009 工作樹內容，尚未合併 main 或發布。分批驗證、實機待辦與整合提交見 [TASK-009-HANDOFF.md](TASK-009-HANDOFF.md)；上方安裝網址仍是既有發布版。

- 20 章、40 次主線遠征；每章兩趟，每趟包含 7 個戰鬥房間，最後一房為守衛戰或首領戰。原六趟索引、前三章體驗及房間數保留。
- 3 名可選角色、5 種主武器、21 種升級、5 種武器進化；可同時搭配連鎖閃電、伴星、星爆、星墜，組出霜雷共鳴或餘燼連爆。
- 守燈旅人起手餘燼之心 1；完成 1／2 趟主線後解鎖逐風斥候／苔紋守衛，分別起手輕靈步伐 1／護燈者 1。工坊 3／4 級解鎖迴風飛環／震地戰錘。
- 進化條件顯示於地圖、升級選單與戰鬥中的構築檢視；升級選項保留未完成的進化材料，無須靠外部攻略。
- 密集普通怪搭配少量特殊怪；23 種一般敵人與 20 位首領。新增 17 個主題場景和不同預警招式，終王分三階段；持盾守衛、投石像、幽影及原三位首領保留原行為。
- 七房節奏：第 1 房累積能力，第 2–3 房逐漸清理怪群，第 4–5 房主武器進化，第 6–7 房迎戰更密集的怪潮。以低營地且專注選進化材料為基準；高營地可更早成型，分散升級可更晚。
- 關末先提示最後一波，再停止增援、清除殘兵、吸收全部掉落與完成升級，最後顯示勝利與獎勵。每房恢復 8% 生命。
- 工坊每級傷害 +8%，燈塔每級生命 +10；可進入第4／8／12／16章時上限依序升至30／40／50／60。書庫上限20，每級經驗與火種 +3%。原1～20級費用保留，21級起每級增加150火種。
- 第4章起依區段將基本火種提高至2～5／6～10／11.5～16／17.6～24倍；每趟首次主線通關另得510×章節倍率，不受書庫或拾荒者加成。重玩不重領，經驗不乘章節倍率。
- 14 隻永久寵物，每次最多一隻出戰，營地點選另一隻即可替換，沒有額外格數購買。舊存檔保留第一隻出戰與全部收藏，已購格數預設退還300／1,200火種一次。沿用同一馴服與保存流程；傷害固定、不繼承玩家升級。原五隻限前三章，九隻後期寵物每兩章登場，曙光星龍只在第20章；新章一般房限第5～6房，機率15%，首領房50%。
- 出戰寵物會自行離隊追擊、選擇攻擊位置，清完敵人或離主角太遠時返回。寵物移速為玩家當前移速 90%。14 隻寵物與 43 種怪物／頭目均有實際移動、攻擊影格；出手特效包含爪痕、吐息、閃電、光束與尾跡，保留 0.5–0.7 秒後消散。本輪單元與 build 已通過，瀏覽器畫面待使用者驗證。細節與驗證見 [ANIMATION-HANDOFF.md](ANIMATION-HANDOFF.md)。
- 每次遠征以約 8–12 分鐘為節奏目標，實際時間取決於配裝、選擇與首領戰；仍需實玩校準。普通／困難可重玩，每局依種子排列遭遇。
- 暫停或切到背景會停止戰鬥；程序被關閉後從房間入口恢復，可能重打當前房間。
- 失敗保留一半本局火種，保留所有永久成長；撤退帶回已收集火種。
- 存檔格式為 v5，自動讀取 v1～v4：沿用008的遷移，保留永久進度、受傷血量、本局能力、growth與寵物遭遇。舊局不補起手或當房寵物抽選，不回血；v1舊解謎房接續新戰鬥房。

2026-09-22 使用者核准 TASK-002／003／004 合併 main 並發布至原手機網站第 7 版，包含角色選擇、外觀、兩把新武器及星墜／乘隙／守燈決意；離線內容版本為 `e327a9a8a958`。預設 keeper 新局含 vitality 1，因此燈塔 0 級為 120 生命；角色起手與書庫相加並受能力上限限制，預覽與新局共用 `startingLoadout`，舊局不重算起手。使用者接受目前四組死亡與自然協同未成型的觀測；具體規格見 PROJECT，後續跨構築平衡仍由 TASK-005 接續，方向見 [下一版規劃](ROADMAP.md)。

本版升級經驗需求為原本的 11 倍；一般房間每批基礎怪量依序為 4、4、5、5、7、10、12，至少四分之三直接生成近身雜兵，其餘依遭遇抽選。普通怪基礎生命增加 20%，每房生命成長由 6.5% 提高到 8%。同場上限為 160 隻。成型前的第 4–5 房採較緩的怪量增幅，將大量增援留到第 6–7 房。

TASK-001 首領更新已完成並獲使用者試玩認可（驗收範圍見 [STATUS.md](STATUS.md)）：依試玩回饋，三位首領普通生命由 3,600／5,200／5,600 提高 25% 至 4,500／6,500／7,000；每 2.5 秒增援由 8 隻增至 12 隻。困難生命仍乘 1.35，平時移速仍為 34／24／36。招式預警 0.8 秒，半血後的追擊另留 0.45 秒間隔並重新預警。守望者衝刺會在預告的場邊終點停止；祭司交替引爆／環形彈幕；幽龍交替環形／鎖定扇形彈幕。既有燃燒、減速、永久加成與死亡後清殘兵／收掉落／單次結算保留。

## 開發與驗證

2026-09-23 起，agent 可執行受影響的單元測試與 build；以下瀏覽器測試由使用者執行。Agent 交付待測步驟與預期結果，不自行開網頁、執行無頭瀏覽器或啟動瀏覽器測試。文件修改只做靜態檢查。模型與測試責任詳見 [AGENTS.md](AGENTS.md)。

需要 Node.js 22.18 以上。

```sh
npm ci
npm run dev -- --port 5173 --strictPort
npm test
npm run build
npm run preview -- --port 4173 --strictPort
npx playwright install chromium
npm run test:browser
npm run test:arena
npm run test:offline
npm run test:android
```

瀏覽器測試需要 4173 的正式建置預覽；機制測試需要 5173 的開發伺服器。報告與畫面輸出到未追蹤的 `artifacts/`。測試使用獨立無痕環境和本遊戲的匯入介面，不讀取個人瀏覽器資料。

`npm run test:android` 在建置後執行，會依序自建本工作樹的預覽／開發／離線測試伺服器並在結束時關閉；全部使用 4180 埠，執行前須確認沒有其他測試佔用。以 Playwright Pixel 5 的 Chrome UA、觸控與畫面尺寸跑完整瀏覽器流程、49 項戰鬥／觸控檢查及離線更新回歸，另驗證私人 manifest 在快取建立前可帶登入憑證讀取，並確認 iPhone 安裝提示保留。Android 報告為 `artifacts/android-browser-report.json`、`android-arena-report.json`，安裝畫面為 `install-android.png`；離線結果輸出至終端。這些是 Chromium 模擬，不含 Android 系統安裝面板、真正 OAuth 登入或手機效能驗收。

`src/core.ts` 為規則與存檔格式，並 re-export `characters.ts`／`weapons.ts`／`upgrades.ts` 的唯一資料表與型別；`src/arena.ts` 為 Phaser 場景、碰撞和單指操作；`src/main.ts` 為營地、主線與存檔操作。`scripts/build-offline.mjs` 將正式輸出全部檔案加入具內容版本的 Service Worker 快取。所有遊玩依賴都在同一來源，無執行時 CDN、帳號 API 或線上關卡。

主線章節／經濟資料在 `src/mainline.ts`，敵人種類在 `src/enemies.ts`，新章預警幾何在 `src/chapter-attacks.ts`；寵物共用 `src/pets.ts`／`src/pet-arena.ts`。新素材的提示、原圖與QC位於 `assets-source/mainline/`，只有執行圖位於 `public/assets/`。

大量進出房間的素材載入回歸：`node scripts/check-mainline-lifecycle.mjs --port=5173`，在同一頁重建1600次場景並檢查動畫影格。主線獨立檢查：`node scripts/check-mainline.mjs --port=4180`、`node scripts/check-mainline-browser.mjs --port=5173`、`node scripts/check-mainline-pressure.mjs --port=5173`。完整遠征使用 `node scripts/check-mainline-balance.mjs --port=4180 --first=16 --last=20 --weapons=staff,halo,hammer,blade`，其他區段依批次指定起訖。加上 `--prior-pets --weapons=halo,blade` 可驗證只用前章可遇的一寵；`--resume` 僅接受來源與案例完全一致的未完成報告，並重跑最後一趟比對結果。這些指令自行啟停伺服器；同埠依序執行，先協調。Android三個檢查亦可另傳 `--port=5173`。

本機檢查涵蓋：規則與 v1 遷移測試、Chromium 手機尺寸與桌面畫面、真正斷網後的新頁面啟動、存檔續玩、備份匯出及無效匯入、結算不重複發獎、武器進化／首領／技能協同、跨幀動畫、預警近戰、160 怪物連爆、30／60 FPS 環繞傷害一致性與完整清場流程。這些不等於 iPhone Safari 實機測試。

`test:arena` 另包含第一章 24 組完整七房遠征：三把武器各以最低工坊解鎖、燈塔 0 級、書庫 0／3 級及四個固定種子驗證。測試用正常移動與傷害，優先處理遠程怪並選擇進化材料；檢查第 4–5 房進化、後段擊殺量、空場時間及清場耗時，每房也會將存檔序列化再還原。逐房紀錄輸出至 `artifacts/balance-report.json`。

新內容的獨立檢查為 `node scripts/check-weapons.mjs --upgrades`、`node scripts/check-upgrades.mjs`（需要本工作樹 5173），以及 `node scripts/check-character-arena.mjs --port=4180`、`node scripts/check-characters.mjs --port=4180`、`node scripts/check-weapons-browser.mjs`（各自啟動／關閉 4180，須依序執行）。`node scripts/check-balance.mjs --weapons --upgrades` 量測新武器七房與能力策略，另以 `node scripts/check-weapon-boss.mjs` 讀取其報告量測成型首領。已交付的七房結果為 36／40 通關；4 組死亡與自然協同未成型留待 TASK-005，不視為全部平衡驗收通過。詳細條件見 [TASK-003-HANDOFF.md](TASK-003-HANDOFF.md)。

首領另以 `npm run test:boss -- --baseline` 在修改戰鬥程式前建立基準，修改後執行 `npm run test:boss` 重用同一批入口檢查點與策略；兩者均需本工作樹的 5173 伺服器。報告為 `artifacts/boss-baseline.json`、`boss-after.json`，包含來源提交、程式及量測工具雜湊、承傷／回血、招式次數與擊殺／收尾時間。覆蓋三首領、三武器、普通／困難、低／中／高營地與同能力預算的技能協同。困難案例沿用普通前六房所得的入口狀態，只隔離比較首領；未到達第七房的案例會另記錄，改用第一章完成前六房的相同武器／營地／種子檢查點測首領，標記 `chapter-one-transfer`。這不代表該章完整遠征已通過。

量測指令檢查卡關與怪量上限，通關／死亡數據另作設計判讀，不以指令退出成功宣稱所有案例通關。本輪調整前報告是本機交接證據，未納入 Git；若要重現此次前後比較須另攜帶該報告，不能在新版建立基準後當成舊版結果。一般回歸仍可獨立按上列正式指令執行。

離線回歸測試另涵蓋缺檔重試、登入頁防誤存、首頁正規化與版本更新；觸控測試涵蓋實際觸控事件、多指干擾、取消與移出畫面。可安裝 Playwright WebKit 後執行 `npm run test:offline -- --webkit`；Windows WebKit 的 `setOffline` 會使最小快取頁面也出現內部錯誤，因此此模式改為中斷伺服器連線驗證快取，不等於 iPhone 飛航模式測試。

待實機驗證：Android 最新版 Chrome 加入主畫面後的圖示、單指操作、切背景暫停、登入往返、更新保留進度與飛航模式冷啟動；iOS 17+ Safari／主畫面、長時間發熱與耗電、兩小時連玩及相隔七天的離線重開。系統持久儲存申請不保證網站資料永遠不會被清理。原生 WebMCP 執行環境目前未連線，兩個選用介面的實際註冊尚未驗證。

## 維護者發布更新

1. 保留原 HTTPS 網址、manifest 的 `id`／`start_url`／`scope`、IndexedDB 名稱與 `.openai/hosting.json` 身分。網站目前仍需登入；manifest 連結使用 `crossorigin="use-credentials"`，依 [Chrome 官方說明](https://web.dev/articles/add-manifest) 攜帶登入憑證。
2. 執行 `npm test`、`npm run build` 與 `npm run test:android`，再檢查受影響的其他功能。建置會依內容產生新的 `sw.js` 快取版本，遊戲更新不依賴手動修改 `package.json` 版號；Save v5 是另一個獨立的存檔版本。
3. 將同一次建置的完整 `dist/` 發布到原網站。合併 main 不等於更新正式站；實際發布另記錄於 STATUS。
4. 在已有舊版與存檔的 Android 主畫面 App 保持連網、檢查更新，確認遠征中無法套用，完成或撤退後才更新。比對存檔、離線版號，再用飛航模式關閉並重開遊戲驗證。若登入到期，使用遊戲內「重新登入以更新」恢復；更新不以重裝或清除資料為步驟。

## 美術來源

使用內建 ImageGen 與 agent-sprite-forge 的 generate2dsprite / generate2dmap 技能製作。`public/assets/` 為執行時素材，`assets-source/` 保留原圖、創作提示、圖集契約與 QC 紀錄。沒有以程式圖形取代角色或場景；程式只繪製操作提示、攻擊預警、血條等功能性圖形。

主角圖集為 4×4、每格 128 px，方向依序下／左／右／上；原敵人與物件圖集為 3×3、每格 128 px；新敵人依批次為 3×3／3×4，同樣每格 128 px。場景只烘焙地面，提燈、機關、寶箱與角色分開繪製，碰撞範圍由場景資料定義。

部署為 Sites 私人靜態網站，`.openai/hosting.json` 對應同一專案。發布時將 `dist/` 打包；不將美術原圖、測試存檔或私人憑證放入公開遊戲輸出。
